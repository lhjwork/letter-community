# 다이어리 디자인 시스템 기획서 — 어드민에서 만들고, 사용자는 고른다

> 작성일: 2026-09-27
> 대상: `letter-admin`(React+Vite) · `letter-my-backend` · `letter-community`
> 전제: [다꾸 기획서](./diary-deco.plan.md) MVP 구현 완료, [갭 분석](../03-analysis/diary-deco.analysis.md) G3(표지)·G4(스티커 수)를 이 기획이 흡수
> 상태: Phase 3(사진 R2·AI 스티커·공개·PG)는 대기. 이 기획은 그와 별개로 진행 가능

---

## 1. 한 줄 요약

**스티커·마스킹테이프·종이·표지·글씨체를 코드가 아니라 어드민 화면에서 만들고 묶어서 내놓는다.** 사용자는 "가을 에디션" 같은 묶음을 고르고, 관리자는 배포 없이 계절마다 새 디자인을 올린다.

지금은 스티커 12종이 `lib/diary-decos.ts`에 박혀 있어 하나 더하려면 코드 수정·배포가 필요하다. 이걸 데이터로 옮긴다.

## 2. 원칙

1. **업로드 없이 시작한다.** 사진(R2)이 대기 중인 것과 같은 이유. 스티커는 SVG path 문자열, 마테는 색+무늬 프리셋, 종이는 선 색·간격, 표지는 색·레이아웃 프리셋. 전부 Mongo 문서 하나(수 KB). 인쇄에서도 벡터 그대로.
2. **미리보기가 곧 편집기.** 어드민에서 값을 바꾸면 옆의 작은 A5 종이에 즉시 반영. 커뮤니티와 **같은 렌더 코드**(`DecoView`, `.diary-paper`)를 쓴다.
3. **기본 세트는 코드에 남긴다.** 지금 12종·6종·5종은 "기본" 에디션으로 항상 있다. 어드민 데이터는 그 위에 얹힌다. DB가 비어도 서비스가 돈다.
4. **켜고 끄기.** 삭제 대신 비활성. 이미 붙인 스티커는 사용자 페이지에 남아야 하므로 자산은 지우지 않는다.

## 3. 자산 종류와 편집 항목

| 종류 | 편집 항목 | 렌더 |
|---|---|---|
| 스티커 | 이름, SVG path(32×32 viewBox), 기본 잉크색, 태그 | 지금 `STICKERS`와 동일 구조 |
| 마스킹테이프 | 이름, 바탕색, 무늬 프리셋(줄무늬·도트·체크·사선·무지) + 무늬색·간격 | CSS background |
| 종이 | 이름, 바탕색, 줄 종류(줄·모눈·도트·무지), 선 색, 간격(mm) | `.diary-paper` 변수 |
| 표지 | 이름, 바탕색, 강조색, 레이아웃 프리셋(가운데 제목 / 상단 띠 / 하단 라벨), 장식 스티커 1개 | 인쇄 뷰 표지 |
| 글씨체 | 이름, Google Fonts family(한글 손글씨 허용 목록에서 선택) | `<link>` 동적 추가 |
| **에디션** | 이름, 기간(선택), 표지 1 + 종이 N + 스티커 N + 마테 N + 글씨체 N, 공개 여부, 순서 | 사용자가 다이어리 만들 때 고름 |

SVG path만 받고 `<svg>` 원문은 받지 않는다. 스크립트·외부 참조가 섞일 여지가 없어서 살균이 필요 없다.

## 4. 사용자 쪽 변화

- **다이어리 만들기**: "에디션 고르기" 카드 한 줄이 생긴다(기본 에디션 + 어드민이 공개한 것). 에디션이 종이·글씨체 기본값과 사용할 스티커 팩을 정한다.
- **꾸미기 패널**: 스티커·마테 탭이 팩별 섹션으로 나뉜다("기본", "가을 에디션"…). 에디션에 포함되지 않은 팩도 "전체" 에서 고를 수 있게 할지는 결정 사항.
- **인쇄 뷰**: 표지가 에디션 표지로 바뀐다. 갭 G3 해결.
- 자산은 `GET /api/diary-design`(공개, 캐시 5분) 한 번으로 받아 기본 세트와 합친다.

## 5. 어드민 화면

```
다이어리 디자인
├─ 에디션        [+ 새 에디션]   이름 / 기간 / 공개 / 구성(표지·종이·스티커·마테·글씨체 체크)
├─ 스티커        [+ 추가]        표: 미리보기 · 이름 · 팩 · 사용중 토글 · 순서
├─ 마스킹테이프  [+ 추가]
├─ 종이          [+ 추가]
├─ 표지          [+ 추가]
└─ 글씨체        [+ 추가]

편집 모달 (모든 종류 공통 골격)
┌──────────────────────────┬──────────────────┐
│ 이름 [          ]        │   ┌── 미니 A5 ──┐ │
│ 팩   [ 가을 ▾ ]          │   │  샘플 글    │ │
│ (종류별 필드)             │   │  + 이 자산   │ │
│ SVG path [텍스트영역]     │   │  붙인 모습   │ │
│ 잉크색  ● ● ● ● ● ● ●     │   └────────────┘ │
│                          │  인쇄 크기로 보기 │
│              [취소] [저장] │                  │
└──────────────────────────┴──────────────────┘
```

미니 A5는 커뮤니티의 `DecoView`·`.diary-paper`를 그대로 가져와 쓴다. 두 저장소가 별개라 **렌더 코드 복사본이 생기는 것이 이 기획의 가장 큰 기술 부채**다(6장).

## 6. 데이터·API

```ts
// DesignAsset (Mongo)
{
  type: "sticker" | "tape" | "paper" | "cover" | "font",
  key: string,          // 데코에 저장되는 값. 예 "autumn-leaf". 변경 불가
  label: string,
  pack: string,         // "basic" | "autumn-2026" …
  data: object,         // 종류별 (path·color / bg·pattern / lineType·lineColor·gap / bg·accent·layout / family)
  enabled: boolean, order: number,
  createdBy, createdAt, updatedAt
}
// Edition
{ key, label, period?: {from,to}, cover: key, papers: key[], stickers: key[], tapes: key[], fonts: key[], enabled, order }
```

| API | 권한 | 용도 |
|---|---|---|
| `GET /api/diary-design` | 공개 | enabled 자산 + 에디션 전체. `Cache-Control: max-age=300` |
| `GET/POST/PATCH /api/admin/diary-design/assets` | LETTERS_WRITE | 자산 CRUD(삭제 없음, enabled만) |
| `GET/POST/PATCH /api/admin/diary-design/editions` | LETTERS_WRITE | 에디션 CRUD |

`Diary`에 `edition: key` 한 필드 추가. `DiaryDeco.src`는 이미 문자열 key라 스키마 변경 없음.

**렌더 코드 공유**: 선택지 두 개.
- A. `DecoView`·종이 CSS를 어드민에 복사 (빠름, 두 벌 관리)
- B. `letter-projects/packages/diary-render`로 뽑아 둘 다 의존 (바른 길, 워크스페이스 설정 필요)
- **1차는 A, 자산 종류가 5개 안정되면 B.** 복사본에는 원본 경로 주석.

## 7. 단계

| 단계 | 범위 | 예상 |
|---|---|---|
| **D0** | 커뮤니티: 카탈로그를 `GET /api/diary-design`과 합치도록 구조 변경(기본 세트는 코드 유지). 백엔드 모델·공개 API. 어드민 없이도 DB에 넣으면 반영됨 | 1일 |
| **D1** | 어드민: 스티커·마테 목록 + 편집 모달 + 미니 A5 미리보기(렌더 복사) | 2일 |
| **D2** | 어드민: 종이·표지·글씨체. 인쇄 뷰 표지 적용 (G3 해결) | 1.5일 |
| **D3** | 에디션: 어드민 묶기 + 사용자 "에디션 고르기" + 꾸미기 패널 팩 구분 | 1.5일 |
| D4 (옵션) | SVG 파일 업로드(R2 준비 후), 렌더 패키지 분리(B) | Phase 3와 함께 |

**총 6일.** D0만 해도 스티커를 코드 배포 없이 늘릴 수 있다(G4 해결).

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 어드민이 넣은 path가 깨져 보임 | 미리보기 필수, 저장 전 `viewBox` 안에 들어오는지 검사(좌표 0~32) |
| 자산 key 변경으로 기존 페이지 깨짐 | key는 생성 후 수정 불가, 삭제 없음 |
| 렌더 복사본 두 벌이 어긋남 | 복사 시 원본 커밋 해시 주석, D4에서 패키지화 |
| 폰트 무한 추가 → 로딩 느려짐 | 허용 목록 8종, 에디션당 최대 4종 |

## 9. 결정 필요

1. 에디션에 없는 팩도 "전체" 탭에서 쓸 수 있게 할지 (추천: 예, 에디션은 기본값일 뿐)
2. 어드민 권한: 기존 `LETTERS_WRITE`로 갈지, `DESIGN_WRITE` 새로 만들지 (추천: 기존 재사용)
3. D0 착수 시점 — Phase 3 대기와 무관하게 바로 가능
