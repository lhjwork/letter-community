# 다꾸(다이어리 꾸미기) 기획서 — 웹에서 꾸미고, 종이 다이어리로 받는다

> 작성일: 2026-09-27
> 대상: `letter-community` (Next.js 16, Tiptap 3, framer-motion 12) + `letter-my-backend` (Express, Mongo)
> 연관: [편지 소인 기획서](./letter-stamp.plan.md) — 스티커 생성 파이프라인·업로드 저장소를 공유

---

## 1. 한 줄 요약

**letter 안에서 매일의 다이어리 페이지를 쓰고 스티커·마스킹테이프·라벨로 꾸민 뒤, 한 권이 차면 그대로 인쇄·제본된 종이 다이어리로 받는다.**

편지가 "한 통을 써서 한 사람에게 보내는 것"이라면, 다이어리는 "매일 조금씩 써서 미래의 나에게 보내는 것". 이미 있는 실물 편지 배송 흐름을 다이어리 한 권 단위로 확장한다.

## 2. 왜 letter가 이걸 해야 하나

| 현재 | 기회 |
|---|---|
| 편지는 쓰면 끝. 재방문 이유가 약함 | 다이어리는 매일 돌아올 이유. 리텐션 장치 |
| 실물 편지는 관리자가 손으로 옮겨 적는 구조라 확장 한계 | 다이어리는 사용자가 꾸민 페이지를 **그대로 인쇄** — 노동 없이 실물화 |
| 손글씨 폰트, 줄노트 종이, Tiptap 에디터, 주소·승인·배송 상태 관리가 이미 있음 | 다꾸 앱을 새로 만드는 게 아니라 있는 부품에 데코 레이어 하나를 얹는 것 |
| 다꾸 앱(하루콩·데이토 등)은 디지털에서 끝남 | 실물 제본까지 잇는 앱은 드묾. letter의 정체성과 정확히 맞음 |

## 3. 컨셉 원칙

1. **종이가 주인공.** 화면은 A5 종이 한 장. 스티커는 종이 위에 붙는 것이지 UI 위에 떠다니지 않는다. (사용자 확정 취향: 떠다니는 그래픽 금지)
2. **꾸민 그대로 인쇄된다.** 화면에서 되는 것만 제공한다. 인쇄에서 깨질 효과(블러, 반투명 겹침, 저해상 사진)는 처음부터 넣지 않는다.
3. **하루 한 장.** 페이지 단위는 날짜. 무한 캔버스가 아니라 정해진 종이 크기 안에서 채운다. 제약이 다꾸의 재미다.
4. **손글씨 기본.** 본문은 NanumJangMiCe. 폰트 선택은 손글씨 계열 3~4종으로 제한한다.
5. **편지와 이어진다.** 받은 편지, 편지 소인을 다이어리 페이지에 "붙일" 수 있다. 이것이 다른 다꾸 앱에 없는 letter만의 스티커다.

## 4. 사용자 여정

```
다이어리 만들기 ──▶ 오늘 페이지 열기 ──▶ 글 쓰기(에디터) ──▶ 꾸미기(데코 레이어)
      │                                                          │
      │  표지·종이 고르기                        스티커 / 마테 / 라벨 / 편지 붙이기
      │                                                          │
      ▼                                                          ▼
 한 권이 차면(예: 한 달) ──▶ 인쇄 미리보기 ──▶ 실물 신청(주소·제본) ──▶ 승인·인쇄·배송
```

- **다이어리 1권** = 표지 + 페이지 N장. 기본은 월 단위(30~31장), 사용자가 페이지를 더할 수 있음.
- **페이지 1장** = 날짜 + 본문(Tiptap HTML) + 데코 레이어(JSON).
- **꾸미기 도구**: 스티커(SVG 팩), 마스킹테이프(반복 패턴 띠), 텍스트 라벨(손글씨 폰트), 편지 스티커(내 편지·받은 편지·소인 이미지). 드래그·회전·크기·앞뒤 순서. **사진 업로드는 MVP에서 제외** — 유일한 사용자 파일이라 오브젝트 스토리지(R2)가 필요해서 Phase 3로.
- **종이**: 줄, 모눈, 도트, 무지, 크림. 기존 `.story-lined` 48px 줄 배경 재사용.

## 5. 화면 구성

```
┌───────────────────────────────────────────────────────────────┐
│ ◀ 9월 26일 (금)  ▶                           [미리보기] [저장됨] │
├──────────────────────────────────┬────────────────────────────┤
│                                  │  스티커 │ 마테 │ 라벨 │ 편지  │
│   ┌────────── A5 종이 ─────────┐  │ ┌───┐┌───┐┌───┐┌───┐      │
│   │ 2026. 9. 26.       [라벨]  │  │ │🌙 ││☕ ││✉ ││…│ …    │
│   │ ═══ 마테 ═══               │  │ └───┘└───┘└───┘└───┘      │
│   │ 오늘은 …(손글씨 본문)       │  │                            │
│   │ …                  [스티커]│  │  선택한 요소:              │
│   │                            │  │  회전 ◐  크기 ▭  앞으로 ▲  │
│   └────────────────────────────┘  │  삭제 ✕                   │
└──────────────────────────────────┴────────────────────────────┘
```

모바일은 종이 아래에 도구 패널이 시트로 올라온다. 종이 비율은 항상 A5(148×210mm = 1:1.414). 데코 좌표는 **종이 폭 기준 % 단위**로 저장해 화면 크기와 인쇄 크기가 달라도 같은 위치에 찍힌다.

## 6. 데이터 구조

```ts
// Diary
{
  userId, title, coverTheme: "linen-coral" | "kraft" | ..., paper: "lined" | "grid" | "dot" | "blank",
  period: { from: Date, to: Date },
  pages: DiaryPage[],
  status: "writing" | "closed",
  physical: { status: "none" | "requested" | "approved" | "printing" | "sent" | "delivered",
              binding: "spring" | "perfect", copies: number, address: {…}, requestedAt, notes }
}
// DiaryPage
{
  date: Date,
  content: string,            // Tiptap HTML — 편지와 동일
  decos: [{
    id, type: "sticker" | "tape" | "label" | "letter",   // "photo"는 Phase 3
    src: string,               // 스티커 id / letterId
    x, y, w: number,           // 종이 폭 기준 % (h는 비율 유지)
    rotate: number, z: number, text?: string, font?: string
  }]
}
```

`physical` 블록은 `Letter.physicalStatus` 흐름을 그대로 복제한다. 관리자 화면(`letter-admin`)의 실물 편지 목록에 "다이어리" 탭 하나를 더한다.

## 7. 인쇄 파이프라인

가장 단순한 경로를 쓴다. **서버에 PDF 엔진을 두지 않는다.**

1. `/diary/[id]/print` 라우트가 페이지 전체를 A5 `@page` CSS로 렌더한다(표지 → 페이지 순, 데코 포함, UI 없음).
2. 관리자가 Chrome에서 열어 "PDF로 저장"(배경 그래픽 켬) → 인쇄 업체에 전달.
3. 인쇄 안전 규칙을 에디터에서 강제: 재단선 안쪽 5mm 여백, 스티커는 SVG(벡터), 폰트는 OFL(나눔 계열). MVP는 래스터 이미지가 없어 해상도 문제가 원천적으로 없다.

서버 자동화(puppeteer)는 운영 서버 RAM(1.9GB)에 무리라 **주문량이 주 10권을 넘을 때** 도입한다. 그때는 dev 서버 분리 계획의 2GB 인스턴스에서 돌린다.

## 8. 비용·저장

| 항목 | 값 |
|---|---|
| 스티커 팩 | SVG 30~50종, `public/deco/` 정적. 무료 |
| 사진 업로드 (Phase 3) | **Cloudflare R2** (10GB 무료, 전송료 없음) + presigned URL 직접 업로드. 사진은 복구 불가 데이터라 서버 디스크에 두지 않는다. 화면용 1600px WebP + 인쇄용 원본 두 벌 |
| 인쇄 (외주, 예상) | A5 무선제본 40p 소량 인쇄 1권 약 8,000~15,000원 + 배송 3,000원. 업체 견적 필요 |
| 결제 | 1차는 실물 편지처럼 **무통장·관리자 승인**. PG(토스)는 월 주문 30건 넘으면 |

## 9. 단계별 계획

| 단계 | 범위 | 예상 | 산출 |
|---|---|---|---|
| **Phase 0** | 다이어리 생성, 날짜별 페이지, 종이 5종, 손글씨 폰트 선택. Tiptap·줄노트 CSS 재사용. 데코 없음 | 2일 | "매일 쓰는 종이" 검증 |
| **Phase 1** | 데코 레이어: 스티커·마테·라벨 드래그/회전/크기/순서(framer-motion drag), 모바일 터치, 자동 저장. 파일 업로드 없음 | 3일 | 다꾸 핵심 경험 |
| **Phase 2** | 인쇄 뷰(A5 @page), 실물 신청(주소·제본·부수), 관리자 승인·상태, 사용자 상태 추적. 기존 physical 흐름 복제 | 2일 | 실물 다이어리 첫 주문 |
| **Phase 3** | (옵션) **사진 업로드(R2 도입)**, 편지 스티커(내 편지·소인 붙이기), AI 스티커(Gemini), 공개 다이어리 열람·공감, PG 결제 | 5~6일 | 차별화·수익화 |

**MVP = Phase 0 + 1 + 2 (7일).** Phase 2까지 가야 "종이로 받는다"는 약속이 성립한다. MVP는 사용자 파일 업로드가 전혀 없어 스토리지·백업·용량 걱정 없이 시작한다.

## 10. 검증 지표

- 다이어리 만든 사용자 중 **7일 내 3페이지 이상** 쓴 비율 (습관 형성)
- 페이지당 데코 개수 중앙값 (꾸미기 도구가 쓰이는지)
- 한 권 완성(20페이지 이상) → 실물 신청 전환율
- 실물 수령 후 2권째 시작 비율

## 12. 결정 필요 사항

1. **다이어리 단위**: 월 단위(추천, 30장 = 제본 적정) vs 자유 기간
2. **제본 형태**: 스프링(펼침 좋음) vs 무선(책 느낌) — 업체 견적 후. 1차는 한 가지만
3. **가격 정책**: 원가+배송 실비 vs 마진 포함. 첫 20권은 원가로 피드백 수집 추천
4. **공개 범위**: 다이어리는 기본 비공개. 페이지 단위 공개 옵션을 Phase 3에 둘지
5. **Phase 0 착수 시점**: 편지 소인 Phase 0과 병행 가능 (겹치는 파일 없음)

**확정 (2026-09-27)**: 사진 업로드는 MVP 제외, Phase 3에서 R2와 함께 도입.
