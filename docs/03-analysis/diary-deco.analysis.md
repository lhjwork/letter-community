# 다꾸(diary-deco) 갭 분석 — 기획서 vs 구현

> 분석일: 2026-09-27
> 기준 문서: [diary-deco.plan.md](../01-plan/diary-deco.plan.md)
> 대상 브랜치: `diary` (letter-community bb94e1d · letter-my-backend 2b69937 · letter-admin 8a64c85)
> 범위: MVP(Phase 0~2) + Phase 3 중 구현된 항목(편지 스티커). 나머지 Phase 3는 대기.

---

## 1. 요약

| 항목 | 값 |
|---|---|
| 점검 항목 | 34개 |
| 일치 | 28 |
| 부분 일치 | 4 |
| 미구현 | 2 |
| **Match Rate** | **88%** (일치 28 + 부분 4×0.5 = 30 / 34) |

MVP의 핵심 약속("웹에서 꾸미고, 꾸민 그대로 종이로 받는다")은 끝까지 이어져 있다. 갭은 전부 **양(스티커 수·표지 종류)** 과 **검증(실기기·테스트 인쇄·지표)** 에 있고, 구조적 갭은 없다.

## 2. 항목별 대조

### Phase 0 — 날짜별 종이

| 기획 | 구현 | 판정 |
|---|---|---|
| 다이어리 생성(제목·기간·종이·폰트) | `/diary` 목록 + 만들기 폼 | ✅ |
| 다이어리 1권 = 월 단위, 페이지 = 날짜 | `Diary.month` + `pages[].date`, 결정 1(월 단위) 반영 | ✅ |
| 종이 5종(줄·모눈·도트·무지·크림) | `.diary-paper[data-paper]` 5종 | ✅ |
| 손글씨 폰트 3~4종 | 장미체·펜·개구·하이멜로디 4종, Google Fonts OFL | ✅ |
| Tiptap·줄노트 CSS 재사용 | `useLetterEditor` 재사용, 폰트·행간만 CSS로 덮음 | ✅ |
| 자동 저장 | 1.5초 디바운스, 날짜 이동 시 즉시 저장, 저장 상태 표시 | ✅ |
| 표지 3종 | 표지는 제목+월만. `coverTheme` 필드 없음 | ❌ |

### Phase 1 — 데코 레이어

| 기획 | 구현 | 판정 |
|---|---|---|
| 스티커 SVG 30~50종 | 12종 (인라인 SVG, 잉크색 7) | ⚠️ 부분 |
| 마스킹테이프 | 6종 CSS 패턴, 찢긴 끝 | ✅ |
| 라벨(손글씨 텍스트) | 있음, 다이어리 폰트 따라감 | ✅ |
| 드래그·회전·크기·앞뒤 순서·삭제 | 포인터 이벤트 드래그, 회전 ±15°+슬라이더, 크기 슬라이더, z 순서 | ✅ |
| 좌표는 종이 폭 % | `x/y/w` % 저장, 인쇄 뷰에서 동일 위치 확인 | ✅ |
| 스냅: 15° 회전 | 버튼은 15° 단위, 슬라이더는 1° | ✅ |
| 스냅: 5% 격자 | 없음 (0.1% 단위 자유 배치) | ❌ |
| 데코 최대 20개/페이지 | 프론트·백엔드 둘 다 제한 | ✅ |
| 모바일 터치 | 포인터 이벤트라 터치 동작, 패널은 아래로 | ⚠️ 실기기 미확인 |
| 사진 업로드 | 결정대로 제외 (Phase 3, R2) | ✅ (의도된 제외) |
| 파일 업로드 없음 | 모든 데코가 SVG·텍스트·편지 참조 | ✅ |

### Phase 2 — 인쇄·실물

| 기획 | 구현 | 판정 |
|---|---|---|
| `/diary/[id]/print` A5 @page | 표지+쓴 페이지, `@page A5 margin 0`, 페이지마다 나눔 | ✅ |
| 화면과 인쇄물이 같다 | 640px 기준 값을 148mm 비율로 축소, 데코 % 좌표 | ✅ |
| 재단 여백 5mm | 안쪽 패딩 24px(≈6mm). 재단선·블리드 없음 | ⚠️ 부분 |
| 서버 PDF 엔진 없음 | 브라우저 인쇄만 | ✅ |
| 실물 신청(주소·제본·부수) | 폼 + 우편번호 검색 재사용, 검증은 실물 편지와 동일 | ✅ |
| 신청 후 편집 잠금 | 에디터·데코·종이·폰트 모두 잠금, 반려 시 해제 | ✅ |
| 관리자 승인·상태 | 관리자 목록, 상태 7단계, 메모 | ✅ |
| 관리자 화면은 실물 편지 목록의 "탭" | 별도 메뉴로 구현 | ✅ (동등) |
| 사용자 상태 추적 | 상태 카드(접수일·제본·부수·관리자 메모) | ✅ |
| 관리자가 인쇄본 열람 | 15분 토큰 링크 (기획엔 없던 갭을 발견해 추가) | ✅ |
| 결제: 무통장·관리자 승인 | 안내 문구만. 금액 입력·확인 흐름 없음 | ⚠️ 부분 |

### 데이터 구조 (기획 6장)

|---|---|---|

## 3. 갭 목록 (우선순위순)

| # | 갭 | 영향 | 크기 | 권장 |
|---|---|---|---|---|
| G1 | 페이지 넘침 시 인쇄에서 잘림 | 실물 품질 | 작음 | 에디터에서 `scrollHeight > clientHeight`면 "종이가 가득 찼어요" 표시. 30분 |
| G2 | 지표 이벤트 없음 | 검증 불가 | 작음 | 페이지 저장·데코 추가·신청 3개 이벤트. 1시간 |
| G3 | 표지 테마 없음 | 실물 첫인상 | 중간 | **어드민 디자인 시스템 기획으로 이관** (아래 별도 기획서) |
| G4 | 스티커 12종 | 꾸미기 재미 | 중간 | 동일하게 어드민 디자인 시스템으로 이관 — 코드 배포 없이 추가 |
| G5 | 5% 격자 스냅 없음 | 정렬 편의 | 작음 | Shift 드래그 시 스냅. 필요해지면 |
| G6 | 모바일 실기기 미검증 | 사용성 | 검증 | dev 서버 배포 후 실기기 확인 |
| G7 | 결제 금액 흐름 없음 | 운영 | 결정 대기 | 가격 정책(결정 3) 확정 후 |
| G8 | 재단선·블리드 없음 | 인쇄 업체 요구 시 | 작음 | 업체 견적 후 필요하면 3mm 블리드 추가 |

**G1·G2는 지금 바로 할 수 있는 작은 작업**이고, G3·G4는 사용자가 요청한 어드민 디자인 시스템이 자연스럽게 해결한다.

## 4. 판정

Match Rate 88%. bkit 기준(90%)에 조금 못 미치지만 미달분이 전부 양·검증 항목이라 **구조 변경 없이 G1·G2만 처리하면 90%를 넘는다.** main 머지는 실물 테스트 인쇄 1회 후를 권장한다.
